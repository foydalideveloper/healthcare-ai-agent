4. HRT Drill-Down — Query Flow Detail

How a user drill-down click translates to a database query and returns data to the dashboard.

// Example: User clicks [2026] then selects [Food] category User Action: Click [2026] + [Food] → Frontend: GET /api/v1/hrt/drilldown?user_id=1&level=2&year=2026&category=food → FastAPI: SELECT * FROM hrt_drilldown(1, 2, 2026) → hrt_drilldown() function: IF level = 2 THEN SELECT * FROM hrt_monthly_food WHERE user_id = 1 AND year = 2026 → hrt_monthly_food VIEW: SELECT month, food_name, SUM(calories) as total_kcal FROM user_food_log GROUP BY month, food_name → Response JSON: { "level": 2, "year": 2026, "data": [ {"month": 4, "food_name": "삼겹살", "total_kcal": 500}, {"month": 4, "food_name": "김치찌개", "total_kcal": 280}, ... ] }

5. Forecasting Engine — Data Flow
// Forecasting Pipeline: HRT Data to Health Predictions Input Sources: user_diagnosis // BMI, BP, fasting glucose, cholesterol user_lifestyle // calories, exercise_min, sleep_hours user_biometric // heart_rate, spo2, glucose_mgdl, stress → Feature Engineering: 65-dimension input vector [BMI, SBP, DBP, glucose, cholesterol, HR, SpO2, steps, calories, exercise_min, sleep_hours, stress, ...] → Model Ensemble: LSTM-Transformer (custom, 65-dim) MIRA (Microsoft, 455M params) TimesFM (Google, 200M params) Chronos-Bolt (Amazon, 200M params) TFT (Interpretable attention) → Prediction Horizons: 30 days // short-term trend 1 year // medium-term projection 10 years // long-term risk assessment → simulation_result table (scenario, horizon_days, predicted_diag_json, rmse) → Digital Twin Comparison: Current user data vs Role-model (std_lifestyle_plan) → twin_comparisons table (hci_gap_json) → Health Score Calculation: HCI (Healthcare Index) → user_health_level DRI (Disease Risk Index) → user_health_level

7. Security Architecture
Row-Level Security (RLS)
All user health tables enforce RLS policies. Users can only access their own data. Policies use auth.uid() matching against user_token.
Dual ID Strategy
BIGINT user_id for internal use (fast joins, indexes).
UUID user_token for external API exposure (prevents enumeration).
Judgement Agent — 4-Level Safety Gate
Level 1 - Auto: Safe queries, general info
Level 2 - Review: AI reviews before action
Level 3 - Confirm: User must confirm
Level 4 - Block: Denied, escalate to doctor
PHI Leak Detection
All agent outputs are scanned for Protected Health Information before delivery. Regex + NER-based detection prevents accidental data exposure in logs or responses.
