## 1. Full Report feature (NEW)

**What it does:** a 60s clip produces several event cards (one per topic segment). Full Report aggregates every event sharing a `source_video` into one consolidated report + a downloadable Word doc.

**Backend**
- `backend/app/services/full_report_aggregator.py` — pure aggregator: dedup OCR (normalized) / facts / enumerations (exact + semantic), merge timeline by window, value_updates by label, concat distinct transcripts, worst audio quality, metrics. Applies the v3.3 quality filter.
- `backend/app/services/word_exporter.py` — streaming `.docx` (9 sections), Korean via **Malgun Gothic eastAsia** font on every run.
- `backend/app/api/lifelog.py` — `GET /api/v1/lifelog/full-report` (JSON) + `/full-report.docx` (StreamingResponse). Arm-scoped via `source_model`, cross-arm when omitted. Uses the repo's httpx `SupabaseClient` (NOT supabase-py).
- `backend/glasses_watcher/ocr_quality_filter.py` (NEW) — pure filter: keeps digits/currency/entities, drops particles/single-chars/garble/all-caps-non-entity/**mojibake**; observation noise filter. 12 unit tests in `tests/test_ocr_quality_filter.py` (all pass).

**Frontend**
- `frontend/hrt-dashboard/app/lifelog/page.tsx` — `📄 Full Report` 6th button (after 🧠 Combined) opens `<FullReportModal>` (collapsible sections + 📥 Download as Word). Reuses the source dropdown. Existing 5 buttons untouched.

**Endpoints (note the real prefix):** `/api/v1/lifelog/full-report` and `/api/v1/lifelog/full-report.docx` (router prefix `/api/v1` + `/lifelog`). The frontend `API_BASE` already includes `/api/v1`.

**Migration:** none — uses existing v3 schema (007/008/009).

**Reference doc:** `test_data/kbs_clip/test_report_v33_fixed_v3.docx` (9 sections, 3 tables, 44 KB).

## 2. v3.3 quality upgrade (NEW)

Three layers, all additive (no extraction-pipeline change beyond the prompt):
1. **OCR quality filter** (`ocr_quality_filter.py`) applied in the aggregator → `all_ocr_text` = meaningful subset; raw rejects move to `ocr_appendix_full`.
2. **LIFELOG_PROMPT v3.2 → v3.3** (`_lifelog_test.py`): observed_facts now 15-30 SUBSTANTIVE (subject+value) statements; enumerated_observations skip particles/garble/"X is visible"; quality over quantity.
3. **Word restructure**: "Overview"→"Key Findings"; prominent "Key Terms Captured" + demoted 8pt "Technical OCR Reference"; **Detailed Observations section removed** (it duplicated observed_facts — option (a)).

**Measured (test clip `20260528144922838.mp4`, gemma4):** observed_facts 17→59 · enumerated 126→27 (0% noise, was 82%) · OCR 766 raw → 416 meaningful + ~258 appendix.

**Polish (final):** filler-fact filter (drops "is still / nearing end / lighting consistent / user observing"); semantic dedup of reworded triplicates (interpreter 3→1, KBS 3→2); timeline sorted chronologically + "—" for empty cells; value-updates column "Changes"→**"Times Observed"**; case-insensitive `ui_elements` dedup.

## 4. Known caveats (carry forward)

On this clip `detect_value_changes` can't pair garbled labels↔values; it lives in `ocr_preprocessor.py` (off-limits this session).
b. **3 date facts not deduped** — one carries unique spatial info ("top left corner") + EN/KO phrasing differs; deliberate (safe similarity threshold, avoid over-merge).
c. **Whisper Korean transcript has minor errors** — hardware/mic limitation of the AIMB-G1 capture, not a pipeline bug.

## 7. Operational reminders

- **Always run the `.venv` Python**, never conda `(base)` or system Python311 (DLL shadowing → WinError 127). Run watchers from a non-conda shell.
- **Whisper is CPU now** — keeps the 32GB GPU free for Gemma 26B Q8 + Paddle. Override to cuda/float16 only for cloud-only-arm runs.
- **One GPU processor at a time** — don't run multiple watchers + a manual clip run together (they contend and time each other out).
- FastAPI `--reload` picks up backend changes; frontend hot-reloads. No restart needed for aggregator/exporter edits.
