## 1. What this project is

**Healthcare AI Agent** for Triple-H Co., Ltd. — Patent No. 10-2025-0145274.

An AI-glasses lifelog pipeline. A user wears **AIMB-G1 smart glasses** that quietly record short video clips throughout the day. The clips are synced to a Windows 11 PC (RTX 5090) via Syncthing, where a 4-arm multimodal LLM pipeline extracts structured "events" (what the user saw, heard, did) and writes them to a Supabase Postgres database. A Next.js dashboard serves the events as a queryable daily timeline with rich modality-separated panels (visual, audio, cross-modal synthesis).

The pipeline currently runs **4 LLM arms in parallel** per chunk: 2 local (Gemma 4 26B A4B + Qwen3-VL 30B A3B), 2 cloud (Llama 4 Maverick via NVIDIA NIM, Gemini 2.5 Pro via Google AI Studio). A PaddleOCR pre-pass injects ground-truth on-screen text into each arm's prompt so the VLM doesn't have to "read" anything it can't OCR.

---

## 2. The goal

Capture **≥95 % of observable content** from each clip — visual (frames, OCR text, panels), audio (transcript, events, speakers), and cross-modal synthesis (what's happening + recall estimate) — surface as structured queryable events.

**Current recall: ~56 % (substring metric) / ~70 % (semantic eyeball metric).**
**Stretch target: ≥95 %.**

## 4. Pipeline architecture in 10 stages

```
1.  glasses (AIMB-G1)
        |  Bluetooth/proprietary
        v
2.  phone (Syncthing-fork)
        |  Syncthing over home WiFi (UDP/TCP 22000)
        v
3.  PC: C:\Users\A\AIMB-Bridge\ (Syncthing drops mp4 here)
        |  watcher.py polls every 1s, dedup via md5(name+size+mtime)
        v
4.  Whisper (faster-whisper large-v3, GPU) ──> transcript
5.  PyAV samples 8 frames (base) or 60 frames @1fps (broadcast detected)
6.  PaddleOCR pre-pass (GPU on Blackwell, despite cu123 wheel)
        - phash dedup of frames
        - DBSCAN multi-panel detection -> ROI re-OCR at 2x upscale
        - cross-frame value-change detection (Korean-numeral aware)
        - splits results into 4×15s sub-windows for prompt structure
7.  4 LLM arms (parallel per chunk):
        - Gemma 4 26B A4B (local Ollama)
        - Qwen3-VL 30B A3B Q4 (local Ollama)
        - Llama 4 Maverick (NVIDIA NIM cloud)
        - Gemini 2.5 Pro (Google AI Studio cloud)
        Each gets: 20 most-distinct frames + transcript + OCR text + value_updates + 4-window structure
8.  Supabase write -> lifelog_event table (Seoul, ap-northeast-2)
9.  FastAPI :8888 serves events to dashboard
10. Next.js :3000 -> /lifelog page -> 5 buttons per event (Ask / More details / 🎥 Video / 🎤 Audio / 🧠 Combined)
```

## 7. What didn't work + how we fixed it

| What broke | Root cause | Fix |
|---|---|---|
| `paddlepaddle-gpu==2.6.2` not in cu123 wheel index | PaddlePaddle dropped 2.x for cu123; only 3.0 betas there | Installed CPU paddle 2.6.2 from PyPI; turned out it inits in **GPU mode on the RTX 5090 anyway** (cu123 kernels work) |
| 1×1 red-pixel vision test crashed Qwen3-VL with `model runner has unexpectedly stopped` | Qwen3-VL's `SmartResize` requires images ≥ 32 px; my 1×1 test pixel violated that | Use 64×64 PNG for all vision smoke tests |
| Q8_0 weights (33 GB) busted the RTX 5090's 32 GB VRAM | Q8 + mmproj + KV cache > 32 GB | Switched to Q4_K_M (19 GB) — quality hit is small for MoE |
| HTTP 400 `value too long for type character varying(30)` on Llama4 source_model | My dynamic source-tag (`meta_llama_4_maverick_17b_128e_instruct` = 40 chars) overflowed VARCHAR(30) | `_model_to_source_tag` now strips vendor prefix + caps at 30 chars |
| Cloud Qwen 3.5 NIM: 127-352 s per chunk, sometimes 274 s | NIM cloud queue + cold starts | Migrated to local Qwen3-VL via Ollama — now 20-40 s |
| Migration 007 / 008 not auto-appliable | Supabase service-role JWT can run DML but NOT DDL via PostgREST | User pastes SQL into Supabase SQL Editor (one-time per migration) |
| Whisper `WinError 127` on some runs | ctranslate2 DLL not loading cleanly in a freshly-spawned shell | Re-run after FastAPI restart usually resolves; non-blocking for OCR pipeline |
| `1조 6천억` Korean numeral fails to parse | Mixed-scale nested multiplication (천 × 억) not in parser | Per-spec fail-soft (returns None); doesn't flag false changes |
| Substring recall plateaus at 56 % despite better captures | (a) ground-truth pool grew with our OCR improvements; (b) 500-cap clips late-frame items; (c) substring match is too strict for OCR noise | Document the metric's limits; treat absolute captured-item count (49 → 81) as the honest measure |
| HTTP 400 inserts after v3.1 code went live but migration 008 wasn't applied | Watcher writes 4 new columns; PostgREST rejects whole batch with `42703 column does not exist` | Apply migration 008 in SQL Editor (done 2026-05-29) |

- **3-4× ROI upscale** on panels < 250 × 250 px (Hana Bank sub-panel) — current 2× isn't enough for tiny currency values like `1,500.40`, `8,424.66`
- **Smart 500-cap**: prioritize items containing digits / currency / percentages over Korean filler text. Hana Bank values would then survive the dedup truncation.
- **Per-window OCR cap** instead of global: 100 items × 4 windows = 400 + 100 reserved for late-frame discoveries
- **Targeted regex patterns** for currency-board layouts (X.XX next to 3-letter currency code = single semantic unit)
- **Higher-DPI rendering**: PaddleOCR's recognition rate improves significantly above 2000 px width — try 1.5× the source frame before OCR
- **Tune DBSCAN `eps`** on the multi-panel detector. Current 12 % of frame diagonal sometimes over-merges sub-panels.

### Wire v3.1 into the other endpoints
- **`lifelog_reanalyze.py`** ("Ask about this clip") doesn't run OCR pre-pass yet. Should adopt the same OCR-injection pattern as `_lifelog_test.run`.

- Consider PaddleOCR ONNX + onnxruntime-gpu for tighter per-frame latency if CPU becomes a bottleneck.
